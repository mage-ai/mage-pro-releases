## Highlights

- **Introduce Data Context for reusable AI-ready data:** Turn a pipeline output or connected source into a prepared, named context that Sidekick can use for questions, previews, and analytics. Inspect its schema, source coverage, and preparation status in Apps > AI > Data, then attach it to a chat instead of rediscovering the source each time.
- **Share dashboards and charts securely:** Create revocable links to a dashboard or individual chart without requiring recipients to sign in. Choose a frozen Snapshot or a Live view that refreshes its captured scope, and set an expiration and optional access code.
- **Schedule dashboard snapshots by email:** With email delivery configured, send dashboards on a schedule as PDF snapshots, with embedded images when supported. Send a test, review delivery history, and retry eligible failures from the dashboard.
- **Create notebook work from an outcome:** Describe what should happen at the start, end, or a selected point between blocks. Sidekick can answer, ask for clarification, or create multiple blocks; manual block creation remains available, including when AI is disabled.
- **Work across Sidekick conversations:** Pin frequently used chats, search chats and saved agents together, and keep artifacts or chat history open in a resizable side panel. Queued follow-ups and chat history recover more reliably across reloads and tabs.
- **Export Data Explorer results:** Download the current query or preview result as CSV, including all returned columns and rows even when table filters hide some of them. Empty successful results retain column headers.

## New capabilities

### Dashboard and chart sharing

  * **Choose how a link stays current:** Share a frozen Snapshot or a Live view that refreshes the saved chart scope every 15 minutes. Sharing supports pipeline-output charts and supported PostgreSQL and MySQL charts; Live requires a runnable saved source and query.
  * **Control access and lifetime:** Set a 1-30 day expiration, optionally require an access code, and revoke links when they are no longer needed. Editors manage their own links; Admins and Owners can manage dashboard links. Recipients do not need Mage accounts, so review the data in the shared view before creating a link.
  * **Inspect shared data:** Recipients can interact with supported chart controls and see the captured or refreshed data time. A Live view can temporarily show its last successful data with a staleness notice while its source recovers.

### Dashboard email delivery

  * **Send recurring snapshots:** When email delivery is configured, set recipients, schedule, time zone, subject, and message for a dashboard. Deliveries include a PDF attachment and can include embedded dashboard images within delivery limits.
  * **Test and follow deliveries:** Send a test without activating the schedule, then save and enable it when ready. View delivery history and retry eligible failures from the dashboard; deleting a dashboard retires its schedule.

### Notebook Add and block authoring

  * **Start from the desired result:** Use the notebook's Add composer at a chosen insertion point to ask Sidekick for an answer, clarification, or one or more coordinated block changes. Generated work stays anchored where you started.
  * **Keep manual creation close:** Add Python, SQL, R, dbt, AI, Markdown, and other supported block types through the manual choices. Workspaces with AI disabled retain the manual Add path without a nonfunctional prompt.
  * **Work faster with blocks:** Reveal insertion controls between blocks on hover or keyboard focus, clear a selected block's saved output, copy a block UUID from run details, and navigate block search results with the keyboard.

### AI Sidekick conversations

  * **Find and organize chats:** Pin conversations, search chats and saved agents together, and use chat-row actions to rename, mark unread, or archive.
  * **Keep context visible:** Open Artifacts, Subagents, All chats, or Archived in tabs beside a conversation. Sidekick expands for a panel and restores space when it closes; a manual resize takes precedence.
  * **Keep follow-ups intact:** Pending messages survive a same-tab reload until accepted, and history loads more consistently when several browser tabs are open.

### Data Context

Data Context gives Sidekick a reusable understanding of a specific data source. Preparation records the source, schema, and coverage so future questions can start from a known definition and be checked against its permissions and query policy. It does not make a source query-ready until preparation succeeds.

  * **Create a context:** In **Apps > AI > Data**, choose **New reusable context** and tell Sidekick which pipeline block output or configured IO source to use. Sidekick asks you to identify an ambiguous source, creates the context, and starts preparation.
  * **Review what was prepared:** Follow preparation stages and open the context to inspect source links, row and column counts, schema meanings, observed column profiles, and a searchable column list. A failed preparation shows its recorded reason and recovery destination.
  * **Use it with Sidekick:** Select a context to attach it to a new chat, then ask for a preview, analysis, or chart grounded in that prepared source. Sidekick checks requested fields and operations against the context policy and explains unsupported requests.

### Data Explorer and chart details

  * **Export returned data:** Export the current successful preview or query result as CSV without rerunning the query. The export includes the returned window, not the entire source table, and protects formula-like text when opened in a spreadsheet.
  * **Inspect a chart's saved query:** Open Chart details to view and copy the retained SQL, MongoDB JSON, or supported search text and see the chart's source. Unavailable or redacted queries remain hidden.

### Deployment configurations

  * **Remove an accidental configuration:** Delete a saved Deploy configuration with confirmation without editing YAML. Existing deployed code and deployment history remain intact.

## Improvements

  * **Data integrations:** Add Google Ads ad-level and asset-level reports for Demand Gen and video analysis, improve paid-media sync metrics and failure handling, and skip individual inaccessible Google Business Profile locations without stopping other locations. Salesforce Marketing Cloud Data Extension syncs can use a global or per-stream inclusive `end_date`.
  * **Connection testing:** Show the sanitized provider or database-driver reason for a failed IO connection test, and test profiles backed by Mage secrets with their resolved values.
  * **Analytics access:** Restore Viewer chart access while honoring the underlying source permissions. Failed dashboard and chart actions show errors instead of appearing to succeed or updating freshness incorrectly.
  * **Chart creation:** Save valid SQL charts with column names such as `input_tokens` without mistaking those names for credentials.
  * **Workspace management:** Load and search large workspace lists more efficiently, and show a usable empty state with Create workspace on fresh installations.
  * **Appearance and navigation:** Improve light-mode control contrast, header and breadcrumb readability, and Sidekick panel styling. Documentation blocks now show only the settings relevant to Markdown content.
  * **Pipeline operations:** Preserve the overwrite choice for conflicting single-pipeline archive imports, and keep run search focused on pipeline and trigger identity rather than run-variable JSON.

---
## Reliability and fixes

  * **Deployment accuracy:** Stop a deployment when a Git command fails, report masked error details, and use a saved GitHub PAT for HTTPS fetches so an older checkout cannot appear to deploy successfully. Deployment OAuth callbacks now complete in the Deploy app instead of being exchanged twice.
  * **Trigger credentials:** Deployments that enable `HIDE_API_TRIGGER_TOKEN` mask API trigger tokens in ordinary responses and omit them from saved trigger configuration. Editors can rotate a token and receive the new value once.
  * **Workspace secrets:** Preserve selected direct Kubernetes Secret references when a workspace is created or its settings are refreshed, without reading the Secret through the Kubernetes API. Existing `envFrom` inheritance is unchanged.
  * **Sidekick stability:** Restore queued follow-ups after reload, prevent empty or delayed chat transcripts across tabs, preserve useful sanitized runtime errors, and make diagnostic log results fit the tool response budget. Sidekick can edit blocks in nested folders and read authorized local project files reliably again.
  * **Pipeline and editor recovery:** Fix nested-block line links that could crash the editor, refresh dynamic child run state after database reconnects, and prevent concurrent dbt runs from corrupting a shared dependency installation.
  * **Orphaned triggers:** Deactivate triggers whose pipelines are no longer present in the current workspace repository during a later scheduler pass, while keeping run history and requesting cancellation of linked active runs.
  * **Permissions and errors:** Keep permission-denied pipeline lists from flashing data, recognize existing API entities in granular permission rules, make workspace-manager deployment restrictions explicit by default, and retain a clear failure state when dashboard or chart actions are denied.
